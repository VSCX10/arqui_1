# 7.1. Catálogo de Aplicaciones

Aplicaciones que forman Qhatu, cada una relacionada con su contenedor del [diagrama de contenedores (6.2)](../../6/6.2/6.2.md) y con las tecnologías elegidas en [4.6.5](../../4/4.6/4.6.5/4.6.5.md). El código está en el repositorio [ulima-arqsoft/arqui262-grupo5-codigo](https://github.com/ulima-arqsoft/arqui262-grupo5-codigo), separado de esta documentación. Se organiza como un monorepo (npm workspaces): un proyecto independiente por aplicación, con su propio `package.json`, `Dockerfile` y pruebas, de modo que cada microservicio se construye y despliega por separado ([ADR-GLO-01](../../4/4.6/4.6.1/4.6.1.md)).

## Estructura de carpetas

La estructura ya está creada e inicializada en el [repositorio de código](https://github.com/ulima-arqsoft/arqui262-grupo5-codigo): cada aplicación tiene su `package.json`, `tsconfig.json` y carpetas; cada microservicio tiene además su `Dockerfile` y expone solo `GET /salud`. La lógica de negocio se implementará en las siguientes entregas.

```text
arqui262-grupo5-codigo/
├── package.json                  # npm workspaces: servicios/* y frontend/*
├── .github/workflows/ci.yml      # lint, tipos, pruebas y build de cada aplicación
├── docker-compose.yml            # PostgreSQL, Redis, RabbitMQ y OpenSearch para desarrollo local
├── contratos/
│   ├── eventos/                  # PagoConfirmado.v1.json, SubpedidoCreado.v1.json, ...
│   └── apis/                     # precios-stock.v1.yaml, cotizaciones.v1.yaml, cobros.v1.yaml
├── frontend/
│   ├── web-qhatu/                # React + TypeScript (Vite)
│   └── backoffice/               # React + TypeScript (Vite)
├── servicios/
│   ├── svc-pedidos/
│   ├── svc-notificaciones/
│   ├── svc-vendedores/
│   ├── svc-catalogo/
│   ├── svc-busqueda/
│   ├── svc-logistica/
│   └── svc-pagos/
└── infra/
    ├── local/postgres/           # script que crea las 5 bases lógicas en el entorno local
    └── terraform/
        ├── modulos/              # servicio-ecs, base-datos, cache, mensajeria, busqueda
        └── entornos/             # staging/ y produccion/ con su terraform.tfvars
```

Todos los microservicios siguen la misma estructura interna, con la lógica de negocio separada de los adaptadores de entrada y salida para que los puertos hacia terceros (`ProveedorIdentidad`, `Courier`, `PasarelaPagos`, `CanalNotificacion`) se cambien sin tocar el dominio:

```text
svc-<nombre>/
├── Dockerfile
├── package.json
├── tsconfig.json
├── src/
│   ├── index.ts                  # Punto de entrada HTTP (Express)
│   ├── config/                   # Variables de entorno y secretos
│   ├── api/                      # Controladores REST /v1 y middlewares (JWT, propiedad)
│   ├── dominio/                  # Entidades, reglas y casos de uso
│   ├── adaptadores/
│   │   ├── entrada/              # Consumidores de eventos (AMQP)
│   │   └── salida/               # Repositorios (pg), clientes REST, terceros, publicador outbox
│   └── salud/                    # GET /salud para el ALB
└── test/
    ├── unit/
    └── integracion/              # Testcontainers: PostgreSQL, RabbitMQ, OpenSearch, Redis
```

# 7.1. Catálogo de Aplicaciones

Aplicaciones que forman Qhatu, cada una relacionada con su contenedor del [diagrama de contenedores (6.2)](../../6/6.2/6.2.md) y con las tecnologías elegidas en [4.6.5](../../4/4.6/4.6.5/4.6.5.md). El código se organiza en un monorepo dentro de la carpeta `codigo/` de este repositorio: un proyecto independiente por aplicación, con su propio `package.json`, `Dockerfile` y pruebas, de modo que cada microservicio se construye y despliega por separado ([ADR-GLO-01](../../4/4.6/4.6.1/4.6.1.md)).

Elementos de infraestructura y código compartido (no son aplicaciones, pero forman parte de la estructura):

| Elemento | Propósito | Carpeta | Decisión |
|---|---|---|---|
| Contratos | JSON Schema de los eventos (`*.v1.json`) y OpenAPI de las APIs entre módulos, verificados por las pruebas de cada servicio | `codigo/contratos/` | ADR-GLO-03, ADR-TAC-CAT-12 |
| Infraestructura como código | Módulos de Terraform reutilizables y un archivo de variables por entorno | `codigo/infra/terraform/` | ADR-CAT-08 |
| Entorno local | `docker-compose.yml` con PostgreSQL, Redis, RabbitMQ y OpenSearch para desarrollar y probar | `codigo/docker-compose.yml` | ADR-TAC-CAT-12 |
| Pipeline | Workflows de GitHub Actions (lint, pruebas, imagen, despliegue); `/.github/` requiere aprobación del docente (CODEOWNERS) | `.github/workflows/` | ADR-CAT-07 |

## Estructura de carpetas

```text
codigo/
├── docker-compose.yml            # PostgreSQL, Redis, RabbitMQ y OpenSearch para desarrollo local
├── contratos/
│   ├── eventos/                  # PagoConfirmado.v1.json, SubpedidoCreado.v1.json, ...
│   └── apis/                     # precios-stock.v1.yaml, cotizaciones.v1.yaml, cobros.v1.yaml
├── frontend/
│   ├── web-qhatu/                # React + TypeScript (Vite)
│   └── backoffice/               # React + TypeScript (Vite)
├── servicios/
│   ├── svc-pedidos/
│   ├── svc-notificaciones/
│   ├── svc-vendedores/
│   ├── svc-catalogo/
│   ├── svc-busqueda/
│   ├── svc-logistica/
│   └── svc-pagos/
└── infra/
    └── terraform/
        ├── modulos/              # servicio-ecs, base-datos, cache, mensajeria, busqueda
        └── entornos/             # staging/ y produccion/ con su terraform.tfvars
```

Todos los microservicios siguen la misma estructura interna, con la lógica de negocio separada de los adaptadores de entrada y salida para que los puertos hacia terceros (`ProveedorIdentidad`, `Courier`, `PasarelaPagos`, `CanalNotificacion`) se cambien sin tocar el dominio:

```text
svc-<nombre>/
├── Dockerfile
├── package.json
├── tsconfig.json
├── src/
│   ├── index.ts                  # Punto de entrada HTTP (Express)
│   ├── config/                   # Variables de entorno y secretos
│   ├── api/                      # Controladores REST /v1 y middlewares (JWT, propiedad)
│   ├── dominio/                  # Entidades, reglas y casos de uso
│   ├── adaptadores/
│   │   ├── entrada/              # Consumidores de eventos (AMQP)
│   │   └── salida/               # Repositorios (pg), clientes REST, terceros, publicador outbox
│   └── salud/                    # GET /salud para el ALB
└── test/
    ├── unit/
    └── integracion/              # Testcontainers: PostgreSQL, RabbitMQ, OpenSearch, Redis
```
